# Paper assets — what each file is, and how to use it

Everything here is generated by `../kps_paper.ipynb`, which calls `../../scripts/paper_assets.py`.
Nothing re-runs a sampler: the source is the generation campaign on ceph plus two scored caches,
`scripts/metrics.csv` (distributional, 1040 rows) and `scripts/metrics_official_full.csv`
(InverseBench's own evaluator over the same results).

Regenerate everything: open the notebook and Run All (~5 min; TARP and MIRA read `tarp.pkl` /
`mira.pkl`, delete those to recompute, ~25 min).

## Tables — `\input{}` them

| file | what it is | where it goes |
|---|---|---|
| `tab_config.tex` | forward model, noise level, prior checkpoint, test instances, per problem | appendix |
| `tab_sampler.tex` | sampler settings for every arm: slope, `N`, levels `T`, sweeps `M`, rank, Krylov iterations, ODE steps, `sigma` range | appendix |
| `tab_main.tex` | **the main-text table**: 4 rows, 384pt wide, verified against a 397pt ICLR column by compiling. Problems are COLUMN GROUPS, not row blocks -- as row blocks the same content ran half a page. Two baseline rows (best, 2nd) + KPS-G N=16 and KPS-H N=512; one benchmark metric per problem, then CRPS and spread-skill, which no published method reports. The em-dashes in those two columns are the argument. | **main text** |
| `tab_main_caption.tex` | the caption for it, carrying what the trimmed table cannot: which methods the baseline rows are, that ensemble sizes differ 16/512/2048, that KPS-H is shown only at N=512, the two caveats, and a pointer to the appendix. `\input` it inside the `table` environment. | **main text** |
| `tab_bench_<problem>.tex` | InverseBench's own metrics, mean ± sd, with the full published field | appendix |
| `tab_bench_<problem>_median.tex` | same, median [IQR] | **use this for black hole** |
| `tab_posterior.tex` | member error, CRPS, SSR, coverage — mean ± sd | main text |
| `tab_posterior_median.tex` | same, median [IQR] | wherever an sd exceeds its mean |
| `tab_mira.tex` | MIRA score ± spread per arm | main text or appendix |
| `tab_ppc.tex` | observation-space metrics beside parameter-space SSR | appendix |

**Which central statistic.** Use the median tables for black hole: KPS-H diverges on up to 4 of
100 instances (one reaches `x_mean_l2` = 27614) and its closure-phase chi-square is heavy-tailed,
with a standard deviation of 39.9 on a quantity whose target is 1. The mean there describes the
tail, not the method. The `failures` column counts divergences explicitly — how often a method
blows up is a result, not something to average away.

## Figures — `\includegraphics{}` the PDFs

| file | what it shows |
|---|---|
| `fig_method.pdf` | **the method illustration**: one sweep as a 2x2 block -- noisy cloud $p(x_t)$, prior draw $p(x \mid x_t)$, Kalman update $p(x \mid x_t, y)$, re-noise $p(x_{t'} \mid x)$, blue the cloud after each step and grey before it -- with the fork stacked BESIDE it so the whole figure is 2.45in tall and fits a column: KPS-H fits one slope by SLR over the cloud, KPS-G averages every particle's exact slope into one map. Both carry a shaded band -- `sigma_y()` is the same two-fold held-out residual for either slope, so both variants estimate it; what differs is the slope it is measured around. Three things have to hold at once and they pull against each other: the band must CROSS the modes, the analysis must visibly MOVE the cloud, and the two modes must stay DISTINCT. The gain is $V/(V+s^2+\sigma_y^2)$ and on a curved $h$ the residual $s^2$ scales with the same spread $V$ does, so spread cancels and the gain is stuck near 0.5 however it is tuned -- which is why early versions looked static. Only the curvature $c$ and the mode position $\bar x$ are free, and mode distinction spends $\bar x$, so $c$ pays: at $c=0.26$ the gain is ${\approx}0.67$, enough to land the cloud from an offset of $1.2\,\mathrm{sd}$ -- close enough that the band still slices each mode. The band is drawn at $2\sigma_y$ or it is a hairline. The mock problem is invented but the operations are real (closed-form denoiser, the actual update), so **no number in it is a measurement**. **The KPS-G panel shows the AVERAGED slope deliberately**: that is the method as formulated, while the code uses per-particle Jacobians as an efficient approximation, which the paper text explains. Do not "fix" the figure to match the code. |
| `fig_particles.pdf` | member error, SSR and 90% coverage against `N`, all three problems. **The main quantitative figure.** |
| `fig_multimodal_row_id{46,38,68}.pdf` | one row -- truth and its observation, then two modes and theirs. The modes reproduce the data about equally while looking nothing alike. **The figure for the UQ argument**; pick one of the three instances. |
| `fig_calibration.pdf` | ONE ROW: the three TARP panels then MIRA, 5.5 x 2.15in, MIRA a little wider since it carries five rotated category labels where a TARP panel carries three numbers. The panels are TALLER THAN WIDE on purpose -- four across a column leaves each 1.25in, and `set_aspect("equal")` then capped their height at 1.25in too, which is what made the curves unreadable. Dropping the square aspect costs the 45-degree diagonal and buys back the vertical resolution; `row_h` sets the height. The key sits under the TARP block, not centred on the figure, since it describes the curves and MIRA has none. **The compact calibration figure**, and a full-width object by construction -- there is no half-column twin, since at `0.5\linewidth` each panel would be 0.69in. KPS-H is drawn at N=64/128/256/512 in a light-to-dark blue ramp, so the particle trend is readable off the lines; KPS-G N=16 keeps its own orange. The key is one centred row below the panels -- only the first blue entry carries the arm name, the rest are bare sizes -- rather than a per-panel legend, which covered the curves it described. MIRA keeps the two flat arm colours. |
| `fig_rankhist.pdf` | pooled per-pixel rank histograms; U-shaped = over-confident |
| `fig_bias.pdf` | fraction of members below the truth — a **bias** diagnostic, not a dispersion one |
| `fig_ppc.pdf` | observation-space vs parameter-space SSR against `N` |

PNGs of each are provided for slides and quick viewing. PDFs embed real fonts (type 42).

## Reading the calibration figures

Standard ensemble-verification names, so a label needs no caption to decode:

- **skill** — RMSE of the **ensemble mean**. What a point estimate achieves.
- **particle RMSE** — RMSE of a single member, averaged over members. What a user of one
  posterior sample sees.
- **spread** — ensemble standard deviation, with the usual `(N+1)/N` finite-ensemble inflation.
- **spread-skill ratio** = spread / skill. **1 is honest**, below 1 over-confident.

`particle RMSE` and `skill` are both **relative** (divided by `||x*||`); say so in the caption.

**A collapsed ensemble shows up as `particle RMSE` ≈ `skill`** — if a single member is as
accurate as the mean, the members are all sitting on the mean. KPS-H on black hole reads
0.511 vs 0.510; KPS-G reads 0.703 vs 0.552, i.e. a real spread. That is an independent read of
the same thing the spread-skill ratio says, and it comes free with the skill column.
- **TARP**: curve on the diagonal is calibrated; below it over-confident. Grey band is the
  binomial spread at the number of instances.
- **MIRA**: 2/3 is calibrated, 1/2 is an ensemble unrelated to the truth. The grey band is
  `sqrt(1/(18L))`, the spread expected from `L` ground truths — a point inside it is not
  distinguishable from calibrated **at that L**. Navier–Stokes has L=10, so its band is wide and
  "inside" means underpowered, not demonstrated calibrated.
- **Rank histogram**: flat is calibrated, U-shaped too narrow, dome-shaped too wide.

All four rank the arms identically, which is why the claim is worth leading with.

## Provenance — three things the paper must state

1. **Black hole is not the benchmark's problem.** `noise_type` was switched from `'eht'` to
   `'vis_thermal'` (commit `b93dfbb`, 2026-09-17) so the Jacobian variant could run, and the
   campaign ran after it. That is a different measurement model, not just a different solver.
   The caveat is repeated as a LaTeX comment inside `tab_bench_blackhole*.tex`.
2. **Navier–Stokes uses `sigma_noise = 1e-4`**, not the benchmark's `0.0` (commit `ab79ef2`).
3. **Inverse scattering matches upstream exactly**, so it is the one directly comparable problem —
   and the one where the published baselines are filled in.

**KPS-H predates the solve fix.** The campaign ran 2026-09-17/18; the `update_h` fix landed 09-21.
KPS-G is unaffected — verified line by line against the campaign commit, not assumed. The black-hole
KPS-H divergences are the most likely thing that fix removes.

**Baselines.** `tab_bench_inv-scatter.tex` carries InverseBench Table 3 (360 receivers,
`sigma_y=1e-4`, our exact configuration). Those numbers were read from the arXiv HTML by an
automated fetch — **verify against the typeset PDF before submission**. Black hole and
Navier–Stokes baselines are in the paper's Appendix A.1, which the fetch could not reach; those
tables still emit placeholder rows.

## Self-tests

`pa.tarp_selftest()` and `pa.mira_selftest()` run inside the notebook and must pass before the
curves are believed. Both reproduce their statistic's known reference values on synthetic data.
They exist because the first version of each reported a calibrated case as badly miscalibrated —
in both instances the fault was the test construction, not the statistic.


## Suggested layout: what goes in the main text

Every figure is built **at 5.5in**, ICLR's text width, so `\includegraphics[width=\linewidth]`
is a 1:1 placement and the type renders at the size it was set in. (Building wider and letting
LaTeX shrink is what turned 8pt labels into 6.4pt, and a 9in-wide calibration figure into 4.9pt.)

**Main text — three figures, about 1.2 pages total.** These carry claims the tables cannot.

| figure | size | what it is there for |
|---|---|---|
| `fig_method.pdf` | 5.5 x 2.45in | the reader's picture of the algorithm, and the one figure that defines KPS-G vs KPS-H. Put it first; every later figure uses those two colours. |
| `fig_particles_main.pdf` | 5.6 x 3.6in | the abstract's "improving further with more particles", on all three problems: accuracy holds, spread/error climbs with `N` but never reaches 1, and KPS-G sits far above KPS-H at 1/32 the ensemble |
| `fig_calibration.pdf` | 5.5 x 2.15in | the differentiating claim, with **two independent instruments** (TARP and MIRA) and their reference values drawn in |
| `fig_multimodal_row_id46.pdf` | 5.5 x 1.1in | the qualitative argument, and the cheapest figure per unit of message: two modes that fit the data about equally and look nothing alike |

If space forces a cut, take it out of `fig_calibration`: restricted to the two 100-instance
problems plus the MIRA panel it drops to roughly 2.7in. Cutting the multimodal row would be the
wrong economy -- it costs 2in and is the only thing in the paper that shows a posterior rather
than describing one.

**Appendix.** All tables, plus:

- `fig_particles.pdf` -- the full three-metric version, adding 90% coverage
- `fig_ppc.pdf` with `tab_ppc*.tex` -- observation space, which separates "collapsed in state
  but honest in observation" (black hole) from "wrong in both" (the other two)
- `fig_rankhist.pdf`, `fig_bias.pdf` -- supporting calibration diagnostics
- `fig_growth_<problem>.pdf` -- what more particles buy, visually, over three instances
- `fig_instances_*`, `fig_samples_*` -- galleries

**What the ladder shows, and where it does not.** Curves move toward the diagonal with N on
two problems and not on the third, so the figure should not be captioned as a uniform trend.
RMS deviation from the diagonal, N=64 -> 512:

| problem | 64 | 128 | 256 | 512 | |
|---|---|---|---|---|---|
| black hole | 0.298 | 0.286 | 0.232 | 0.192 | monotone toward calibration |
| Navier--Stokes | 0.555 | 0.522 | 0.309 | 0.323 | improves, then flat within 10 instances |
| inverse scattering | 0.527 | 0.547 | 0.552 | 0.558 | monotone the WRONG way, though only 0.03 |

None of the twelve reaches the diagonal, which is the honest headline: more particles help on
black hole, do nothing resolvable on inverse scattering, and calibration is not bought by N
alone. On inverse scattering every KPS-H curve sits on the floor of the panel -- the ensembles
are far too narrow at every size -- while KPS-G at N=16 is the closest arm to the diagonal
anywhere except black hole.
